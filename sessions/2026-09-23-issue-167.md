# Issue #167 — graph mutation bookkeeping

## Scope and acceptance criteria

Make private node/edge bookkeeping invariants explicit and share repeated
cleanup/rebuild sequences without changing public API, selectors, complexity,
edge-ID semantics, or error messages. Cover a newly exposed stale edge-ID
lookup after `clear()` and move operations.

## Decisions

- Keep helpers private to `Graph`; no new `nxpp::detail` or public API surface.
- Group edge attribute/index cleanup and descriptor-map rebuilds only where
  multiple mutation paths already use the same sequence.
- Keep staged-flow invalidation at existing successful-mutation boundaries,
  preserving rejected and guarded no-op behavior.
- Preserve the preparation of the generated single header as a local test step;
  do not version `dist/nxpp.hpp`.
